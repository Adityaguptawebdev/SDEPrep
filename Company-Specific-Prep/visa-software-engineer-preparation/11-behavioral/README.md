> ⚠️ No fake stories here — every story slot is **[CUSTOMIZE WITH YOUR ACTUAL EXPERIENCE]**. Prepare 6–8 real stories and reuse them across questions.

## Visa's official Leadership Principles — map every story to one

From [Visa Leadership Principles](https://corporate.visa.com/en/about-visa/leadership-principles.html) (a candidate saw "Collaborate as OneVisa / Execute" in a round agenda — [LC-6834477](https://leetcode.com/discuss/post/6834477/visa-sde-1-by-anonymous_user-y545/)):

| Principle | Behaviours (official wording) | Stories to tag |
|---|---|---|
| **Lead courageously** | act like an owner · think big and challenge the status quo · hold ourselves and each other accountable | ownership, disagreement, failure |
| **Obsess about customers** | listen and learn from customers · dream, design and build the future of payments · sell with pride and purpose | a user problem you fixed, performance work |
| **Collaborate as one Visa** | champion inclusion and diversity · encourage constructive debate · enable each other to succeed | conflict, helping a teammate, cross-team work |
| **Execute with excellence** | decide quickly and move fast · deliver seamlessly · learn from our mistakes | deadline pressure, production bug, prioritisation |

## STAR in 90 seconds

```
 S  Situation   1–2 lines: team, product, stakes
 T  Task        what YOU had to do (not the team)
 A  Action      3–4 specific steps YOU took — the longest part; use "I"
 R  Result      a number or concrete outcome + what you learned / would do differently
```

## Question bank with frameworks

| Question | Framework (fill with your story) |
|---|---|
| **Tell me about yourself** | 60–90 s: present (role, stack, 1 impact number) → past (degree, how you got into full-stack) → future (why this Visa role). [CUSTOMIZE] |
| **Why Visa?** | see [Why Visa — facts vs strategy](01-why-visa-company-and-role.md) |
| **Why should we hire you?** | 3 matches to the JD: (1) Java/Spring + React production experience, (2) a specific impact, (3) learning speed/ownership — each with evidence [CUSTOMIZE] |
| **Biggest achievement** | S/T: context · A: what you did differently · R: metric (latency, bugs, time saved) [CUSTOMIZE] |
| **Most difficult bug** | symptom → first wrong hypothesis → how you narrowed it (logs, repro, bisect) → fix → prevention (test/alert) [CUSTOMIZE] |
| **Conflict with a teammate** | disagreement about *what* (not a person) → you listened/asked for data → agreed on criteria → outcome → relationship after [CUSTOMIZE] |
| **Disagreement with your manager / lead** | respectful: raised with data + a proposal → accepted their decision or they accepted yours → "disagree and commit" [CUSTOMIZE] |
| **Ownership** (asked repeatedly) | something outside your ticket you noticed and fixed/drove to completion, without being told [CUSTOMIZE] |
| **Failure / mistake** | real mistake (e.g. a bug you shipped) → you owned it quickly → fix → what you changed so it can't recur. Don't pick a fake failure [CUSTOMIZE] |
| **Learning something quickly** | new tech/domain, deadline, how you learned (docs, small POC, asking), result [CUSTOMIZE] |
| **Working under pressure** | deadline or incident → prioritised → communicated early → shipped / mitigated → what you'd improve [CUSTOMIZE] |
| **Handling ambiguity** | unclear requirement → clarifying questions, assumptions written down, small version first, feedback loop [CUSTOMIZE] |
| **Prioritisation** | multiple asks → impact vs effort, deadlines, talked to stakeholders, said no/later to something [CUSTOMIZE] |
| **Team collaboration** | worked with backend/QA/product: contract first, demos, unblocked someone [CUSTOMIZE] |
| **Feedback you received** | specific feedback → what you changed → evidence it improved [CUSTOMIZE] |
| **Why are you leaving your current role?** | positive and forward-looking: scale, payments domain, engineering practices, learning — never criticise your employer [CUSTOMIZE] |
| **Career goals** | 1–2 years: strong engineer owning features/services end to end; 3–5: deeper in distributed systems/payments, mentoring |
| **"This job can be monotonous — how do you deal with it?"** ([LC-6618617](https://leetcode.com/discuss/post/6618617/visa-inc-sde-1-interview-experience-acce-5got/)) | find learning inside routine (automation, tests, performance), ask for stretch tasks, focus on impact [CUSTOMIZE] |
| **"How do you stay up to date? What do you think about GenAI? Which AI tools do you use?"** (3 EC/NCG reports) | tools you actually use + a responsible workflow (you review/test all output, no secrets/customer data in prompts) + one concrete productivity example + limits you've seen [CUSTOMIZE] |
| **"What should I tell my team you're best at?"** ([LC-1827912](https://leetcode.com/discuss/post/1827912/visa-sr-software-engineer-bangalore-2022-h887/)) | one specific strength + proof, e.g. "turning vague frontend requirements into working, tested features fast — like X" [CUSTOMIZE] |
| **Ethical dilemma** ([LC-6753253](https://leetcode.com/discuss/post/6753253/visa-sde1-315-lpa-6-month-15-year-exp-oa-5asi/)) | e.g. pressure to skip tests / hide a bug: raise it, explain risk to customers, propose a safe option — payments companies care about this |

## Questions to ask the interviewer (pick 2–3)

1. "What does the team own, and who are its users — internal teams, issuers, merchants?"
2. "What does a typical sprint look like — new features vs maintenance/on-call?" (one ex-employee's post felt it was mostly patches on older tools, [LC-7139305](https://leetcode.com/discuss/post/7139305/amazon-sde1-university-hiring-by-okbhr20-ypy0/) — a single opinion; this question checks it politely)
3. "What would success look like for me in the first 6 months?"
4. "How is the team using GenAI tools in development?"
5. "What's the tech stack, and how do you handle reliability — on-call, SLOs, incident reviews?"

**🗣️ Interview mein aise bolo**: "Main har jawab STAR mein doonga, 'we' nahi 'I' pe focus, aur end mein number ya learning ke saath. Kahani sach honi chahiye — follow-up mein detail poochhenge."
